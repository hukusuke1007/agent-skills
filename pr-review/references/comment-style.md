# レビューコメントの書き方

PRに付けるレビューコメントの下書きの規則である。チームに別の決まり（接頭辞、敬体など）があれば、それを優先する。

- 下書きは作業ディレクトリの `comment-draft.md` に保存し、指示があるまでPRに投稿しない。
- 冒頭は `[imo]` で始める。`[中]` のような重要度のラベルは付けない。重要度は `review.md` に書く。
- 要点だけを書く。1つの指摘は、次の順にする。
  1. 要点の1文。
  2. 対象の箇所（ファイルと行の箇条書き）。
  3. 問題になる理由（2〜3文）。
  4. 提案（1つ）と、最小のコード例。
- 提案には、作者がそのまま選べる具体的な対応（実装例、ログの内容など）と、該当するファイルパスを添える。指摘がテストの不足そのものであるときは、追加するケースを提案に書く。
- 検証の経緯、別の案、補足（修正に合わせて追加するテスト、対象外とした範囲、境界の注意など）はコメントに書かず、`review.md` に残す。
- 期間や閾値などの値は、幅や選択肢で示さず、「期間を決めて（例えば1日）」のように具体的な値を1つ示す。
- コード例は、変更する行と、その位置が分かる最小限の目印だけにする。
- 対応は「〜するのはどうでしょう」のような提案の形で書く。「〜してください」「〜していただけますでしょうか」のような命令や依頼の形にしない。
- 「〜にはならないと理解しています」のような、レビュアーの理解や推測を表明する文を書かない。根拠のある事実と提案だけを書く。
